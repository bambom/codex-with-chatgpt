## 2. 不变的产品边界

- 新建首页“UI 设计”入口，独立标识可用 `ui-design`；复制 AI 图层相关入口、客户端业务和服务器业务后改写，独立注册、构建和接线。
- 保留原 `magic-layers` 按钮、原窗口、任务和保存流程；不通过新增 mode 承载新产品。
- **`MagicGameClient/src/app/game-ui` 是另一条开发线，不得作为本任务的窗口、作者核心、保存链路或服务器基础。** FGUI 仅为输出目标之一。
- 新设计属于现有主页项目体系，复用真实设计身份、目录、账号、设计授权和公共素材存储。
- 标准作者文档是唯一保存状态；画布为可重建投影，会话状态与正式文档分开。所有开放的编辑操作映射到标准命令和同一 Undo/Redo 历史。

GPT 完成完整设计、美术处理、拆图补全、真实 RGBA、真实文字、UI 语义、组件树、布局与原尺寸拼接 PNG，并记录来源、字体替代、假设和未知业务绑定。平台不重新承担这些制作工作。

插件负责获取平台规范、准备与预检、真实文件上传、候选提交、定位修复和回执查询。平台维护规范、正式正文、素材、修订、接收校验和按需导出。新插件流程不生成 PSD/FGUI，也不要求先配置 FGUI 工程才能拼接 PNG。

## 4. 按门槛推进

| 阶段 | 必须交付与验证 |
| --- | --- |
| P0-A：契约 | 平台维护的正文/命令 Schema、中文语义、能力表、API/状态与数据库约束设计、稳定序列化/hash 向量、完整样例和正反案例；Java/TypeScript 一致。确定设计类型绑定、现有登录态接线和渲染执行边界。 |
| P0-B：画布 | 新按钮、新窗口、复制后的独立业务目录和真实构建接线；用嵌套容器、RGBA、真实文字、按钮双实例/覆盖验证拖动、中文输入、换图、Undo/Redo、投影销毁重建及独立保存端口。 |
| P1a/P2a：最小闭环 | 真实身份/目录/权限、固定素材、标准修订和可查询回执；移动/改字/换图后保存关闭，从主页重开并核对；旧基线拒绝；受控重启服务后仍能读取。 |
| P1b：完整接收 | 原材料与完整包、上传恢复、候选版本、校验、共享素材归档、有限三方合并、最终结果重校验、权限/幂等/故障恢复；确定插件授权协议。 |
| P2b：完整编辑 | 补齐已定控件、组件/状态与属性编辑、冲突处理，以及标题/复制/移动/回收/还原/分享/封面等生命周期；开放操作均可保存重开。 |
| P3：插件 | 使用真实平台规范、服务授权和回执，完成全稿生产、上传、错误修复和正式提交；不依赖目标引擎配置。 |
| P4：平台导出 | 固定修订的持久 PSD/FGUI 任务、执行租约/重试/取消、准确产物、下载及实际验证。 |
| P5：未来回写 | 目标绑定、回读、各目标基线、受管范围合并及更多引擎，后续单独安排。 |

客户端与服务器在冻结契约下可以分别推进，但先共同完成 P1a/P2a，再扩展 P1b/P2b。不要等完整上传体系和完整属性面板各自完成，才首次验证保存。P1a/P2a 的通过不等于完整 P1/P2 完成。

P0-A 的首版契约须定义 Button、Input、Slider、Progress、List 的真实语义和合法/非法案例；P0-B 的按钮样例仅验证核心通路。首个布局验证范围为固定 2D 像素画布、嵌套局部坐标和轴对齐尺寸。未实现能力明确拒绝或关闭，不把文字/控件降为图片，不静默丢弃扩展。

P0-B 必须证明单一标准历史、稳定节点映射、真实文字输入、实例覆盖保留和旧保存链隔离。若失败，记录具体端口与最小复现，修复后再验证；不能以原生 JSON 和标准 JSON 双写、替换成 game-ui 核心或只通过 reducer 测试来绕过门槛。

## 5. 接收、合并与授权的关键约束

接收顺序：获取规格和上下文 → 建立提交 → 上传真实文件 → 固定候选 → 校验 → 带版本条件保存 → 查询正式回执。规范、正文、清单和固定素材分别有明确身份与摘要。未完成上传不能被正式修订引用。

同一作用域/幂等键只能绑定同一请求指纹，数据库约束仲裁并发；重试返回原结果，回执丢失按原身份查询。同一键更换内容必须拒绝。候选变化递增 draftVersion，使旧报告失效；迟到报告不能更新新候选。

首版先做准确基线保存，再补齐有限自动合并。GPT 换图与用户移动节点仅在无关联尺寸/裁切等冲突时合并；文字与自动尺寸、图片与九宫格、数值范围与当前值等联合校验。未支持的合并返回定位冲突，不把 expectedRevision 改成最新值后重发旧全文。

合并形成的实际结果必须重新校验，最终事务再核对校验时的 head；发生变化则重新合并校验或返回冲突。回执分开记录提交候选和正式修订的正文/manifest 摘要，包含实际基线、合并 head、规范版本、正式修订和 validationId。修订、精确依赖、head 与成功回执在同一业务事务中写入。

引擎无关的布局求值和 PNG 重建前置到 P0/P1，不等 P4。GPT 拼接图绑定候选，用户编辑或合并后的修订生成自己的预览，不沿用旧图的视觉 PASS。确定性重建不等于重新理解和拆分图片。

新窗口使用现有真实用户登录态。P1 明确插件服务连接的配对/签发、范围、保存、过期/续期和撤销；P3 验证真实闭环。工作区连接不等于服务器登录，不复制浏览器 Cookie，不冒用管理员，不让模型指定 actor/owner 或读取凭证。连接权限与当前设计权限取交集。

共享设计接纳素材时，在设计锁下复核真实权限，并冻结为该设计长期可用的存储依赖；不能长期依赖协作者临时文件。新正文不进入原生 baseline/Ripple，不复用旧 MagicLayer job 作为新业务记录。数据库与对象存储不宣称全局原子，残留内容遵循引用和保留策略。

## 6. 导出与交付

平台导出任务固定设计修订、正文/素材/字体版本、导出器版本和真实目标配置。PSD 保留独立图层、分组、原画布、完整合成和隐藏参考稿；FGUI 按实际源码/样例生成原生资源引用、控件和实例关系。持久任务处理租约、崩溃、重试、取消和迟到结果，不把旧修订产物当成最新结果。

指定电脑目录由平台桌面端或本机交付端处理，目录配置不混入通用作者格式。PSD 回读、FGUI 静态检查、实际编辑器导入与运行时交互分别报告。

## 7. 工作与验收要求

用户已授权提交和推送本任务相关改动，无需反复询问。按仓库边界提交，保留无关改动，不强制推送。每阶段报告代码和文档变更、规范/构建指纹、真实验证、提交号、剩余事项及下一步。

第一条完整链：**新按钮创建设计 → 新窗口读取标准 → 移动嵌套节点/改字/换图 → Undo/Redo → 保存回执 → 关闭 → 主页重开 → 核对坐标、语义、实例与素材版本。** 同时验证原 AI 入口、任务、插入、Undo、保存和重开。

最终分别报告：契约符合性、客户端构建与启动、新窗口编辑、保存重开与生命周期、插件端到端提交、PSD 回读、FGUI 静态检查、编辑器实际导入、运行时交互。未执行项标记“未验证”；文件存在、语法通过、模拟回执和旧流程测试不能代替新功能验收。

可由源码与实验确定的技术细节在 P0 中直接作出决定、写入契约并验证。只有改变产品边界或需要外部授权等关键事项才集中询问，继续不依赖它的工作。不要以重复总体架构讨论或仅列出 TODO 作为完成结果。
