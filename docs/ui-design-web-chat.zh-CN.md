## 本轮交付

用户在 ChatGPT 普通网页聊天中提交图片和要求，或要求修改已有设计。业务只有两种：

1. 图片拆分：网页 ChatGPT 完成图片理解、裁切、蒙版、补图、文字、图层、布局及扩展语义，生成标准正文和全部真实文件。
2. 修改标准设计：网页 ChatGPT 读取授权设计的当前正文与素材，保留未修改对象的稳定 ID，生成修改后的完整标准结果。

插件只做授权、规范和输入读取、文件传输、格式/完整性校验、保存、错误回传与客户端结果接收。不得用插件的本地裁切、图层重建或模型 API 补做网页没有完成的工作。平台独立渲染用于验证和显示，不生成生产者缺失的素材或证据。

统一网页插件保留 13 个基础工作区工具，并增加两个设计业务工具；规范、开始、读取素材、提交和状态是这两种设计业务的传输阶段。旧素材重建、迁移及本地 UI 生产接口保留独立开发使用。普通文件与命令能力不得被用来替代 ChatGPT Web 的图片或设计生产。

## 数据与状态

普通网页 Chat → 已授权固定 HTTPS MCP → 客户端主动连接的通信代理 → 平台校验与保存 → 原生编辑器接收。

采用 ChatGPT 原生文件参数 `openai/fileParams`，接收真实 `file_id` 与临时 `download_url`。网页生成的标准结果包包含 `document.json`、`manifest.json` 和清单中的原始字节。包内相对路径是数据标识，不是用户需管理的工作区目录。插件自动传送；内部保留用于恢复，不需要用户下载、搬文件或手工导入。

每次业务绑定 request ID、design ID、checkpoint、base revision 与输入摘要。相同请求恢复原任务；不同内容不得复用同一身份。只有持久 COMMITTED 回执代表完成。网络超时返回可查询任务；版本冲突和验证失败保留候选，由网页 ChatGPT 按字段修复，不自动覆盖草稿。

接收文件严格限制 HTTPS 来源、重定向、文件大小、解压后总量、路径、清单和哈希；下载地址、账号凭据不出现在日志或业务回执。返回设计素材继续检查原设计权限和固定版本。

## AI 执行协议

| 阶段 | 参数与结果 |
| --- | --- |
| `spec` | 默认 `section="summary"`，只读工作区身份、授权设计与当前 context；按需读取 `authoring`、`manifest`、`example` 等规范节。 |
| `begin` | 选择一个业务工具并生成一次 UUID `request_id`，多设计授权时明确 `design_id`。返回固定 checkpoint、base revision、submission ID 与输入。首次拆图要求空白且未发布的设计；修改要求已有标准修订。 |
| 网页制作 | 在普通网页 Chat 内完成全部文件。输入 ZIP 的 `input.json` 提供当前正文和固定素材清单；素材位于 `files/<清单中的 path>`。结果 ZIP 根目录放 `document.json`、`manifest.json`，其余文件位于新清单声明的精确路径。 |
| `submit` | 沿用同一 `request_id`，将网页生成的真实 ZIP 作为原生 `result_file` 参数传入。该文件对象由 ChatGPT 提供，不编造 URL/file ID，不要求用户下载或搬文件。 |
| `status` / `resume` | 查询或继续同一任务。已保留的 ZIP 可在临时下载地址过期后恢复；有准备提交身份时复用同一身份。确认平台保留完整提交回执后自动释放冗余传输 ZIP，保留任务身份。未确认包不自动清除。 |
| `transport_status` | 转发响应超时时，传返回的 `relay_request_id` 查询原响应，再根据业务状态继续。不要重发未知结果的修改。 |

`WAITING` / `CLAIMED` 表示等待原生编辑器接收与保存；AI 查询状态，必要时 `resume`。`CONFLICT` 保留候选及原生草稿，先向用户说明差异，再在网页制作新结果。接收并不要求关闭编辑器。客户端尚无新接收代码时不会自动完成已打开编辑器的交付，不能因此绕过活动通道保护。

恢复补丁处理 `CLAIMED` 租约过期且编辑器已关闭的情况：若结果已准确落盘，只补齐完成回执；若设计此后未修改，直接恢复导入；若已有后续修改，返回冲突并保留候选。活动编辑器仍由原生接收通道处理，恢复流程不得旁路覆盖。

原生文件下载目前只允许 HTTPS `oaiusercontent.com` 及其子域、公网 IPv4，拒绝任意地址和跨来源重定向。**这是一项尚待实际账号验证的兼容性约束**；官方文件参数文档未承诺固定文件域名。真实 PoC 必须核对附件域名、临时 URL 有效性和网页工具接收文件能力；遇到其他来源先核实官方证据后调整受限策略，不直接允许任意 URL。
